File layout: 16-byte header: magic "RP6502\x00\x00\x00\x00" (12 bytes, ASCII + 4 zero padding) followed by a single 4-byte BE "program size" field (total 16 bytes). After the header, the payload is a concatenation of 16-byte "pages". Each page has: page ::= <12-byte BE offset> <4-byte BE flags> where the offset is the page’s linear address in the 6502 address space (0..0xFFFF) and flags are 4 bytes BE (bit 0: writable, bit 1: executable, bits 2-31 reserved zero). Mutator strategy: - keep header and page framing intact - target the 4-byte BE "program size" field with overflow-prone values (0..0xFFFF) - flip the 4-byte flags field per-page, only toggling bit 0 (writable) and bit 1 (executable) through their valid combinations plus a few invalid edges (e.g., both set, neither set) - DO NOT recompute any checksums; the format has none - mutate at most one page per iteration to keep cost tiny PER-MUTATION COST: keep each mutation tiny — at most ~16 bytes of write. AFL's havoc/cmplog will compose larger runs across iterations.
